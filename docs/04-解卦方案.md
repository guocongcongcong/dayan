# 解卦方案：它其实是「检索」，不是「生成」

> 你上一轮说"解卦不需要"，这一轮又问"方案一的那个解卦呢"。
> 这两句不冲突 —— 我的建议是：**把它们拆成两个东西**，下面说为什么。

---

## 1. 先解决一个结构问题：摇卦和解卦不是一个产品

| | 摇卦 | 解卦 |
|---|---|---|
| 用户心态 | 快、私密、一次性 | 慢、要读、反复看 |
| 停留时长 | 3 秒 | 3~10 分钟 |
| 失败代价 | 无（再摇一次） | 高（误导决策） |
| 屏幕 | 一屏 | 需要长文排版 |

塞进一个页面，两边都会难受：摇卦被多余的字拖慢，解卦被按钮挤成碎片。

**建议：摇卦保持现在这样（一个按钮，干净）。解卦做成第二屏 / 第二个入口，想看的人点进去。**

这也是为什么我建议**解卦这一版不做**——不是不重要，是它值得单独做对。

---

## 2. 一个关键发现：高岛原文自带「问题分类」

我扒了一遍语料，发现高岛每一爻的断语都是这个结构：

```
断曰：（针对当时求占者的长断，几十到几百字）

【占】　问时运：刚变而柔，运途不正，气量浅狭，是以多凶。
○　问战征：主将才力微薄，不能包容众军，防有兵变之祸。
○　问营商："包无鱼"，有囊里空虚之象，何以获利？
○　问功名：鱼喜得水，人喜得名，无鱼则水涸，无名则人穷，故凶。
○　问婚姻：婚姻之道，重在生育，"包无鱼"，言无胎孕也。凶。
○　问家宅：《象》曰"远民"，此宅必在民居相远之地，是孤村也。
○　问疾病：鱼阴象，无鱼是阴已亏极，阳不能包，必凶。
○　问六甲：生女。
```

**高岛早就把"你问什么"这件事分好类了。**

实测解析结果：

- 384 个爻级断语里，**372 个能结构化成「类别 → 断语」**（96.9%）
- 一共 34 个原始类别，归并后是 12 个现代问题桶
- 每爻平均带 **7~8 个**分类断语

各主要类别的覆盖率：

| 类别 | 覆盖爻数 | 占比 |
|---|---|---|
| 战征（竞争/对抗） | 336 | 88% |
| 六甲（怀孕生育） | 337 | 88% |
| 家宅（买房/家庭） | 313 | 82% |
| 功名（事业/考试） | 279 | 73% |
| 营商（生意/投资） | 275 | 72% |
| 时运（综合） | 270 | 70% |
| 疾病（健康） | 258 | 67% |
| 婚姻（感情） | 222 | 58% |
| 失物 | 117 | 30% |
| 讼事（官司） | 107 | 28% |

## 3. 所以「解卦」到底是什么

拆开看，是三层，**只有第三层需要 AI**：

```
第 1 层  取辞      数字 → 该看哪一卦哪一爻          ← 纯规则，已实现
第 2 层  检索      从该爻里取出「与你问题相关的那段」  ← 纯查表，96.9% 数据已备好
第 3 层  转述      把文言讲成今天的话               ← 这才是 AI 的活
```

**80% 的解卦价值在第 2 层，而第 2 层根本不需要 AI。**

大多数"AI 解卦"产品跳过第 2 层，直接让模型读整卦然后自由发挥——这就是它们胡说八道的根源。你手里这份语料，恰好让第 2 层变得极其可靠。

## 4. 现代问题 → 高岛类别 映射表

用户不会说"问营商"，他会说"我想辞职去做自媒体"。所以需要一张映射：

| 用户其实在问 | 高岛类别 |
|---|---|
| 感情、复合、要不要结婚 | 婚姻 |
| 跳槽、升职、要不要接 offer | 功名 |
| 考试、考公、面试 | 功名 |
| 做生意、投资、合伙 | 营商 |
| 财运、这笔钱能不能赚 | 营商 |
| 健康、病情 | 疾病 |
| 买房、搬家、家庭矛盾 | 家宅 |
| 官司、纠纷、仲裁 | 讼事 |
| 找失物、丢东西 | 失物 |
| 等一个人、对方会不会回 | 行人 |
| 怀孕、生育 | 六甲 |
| 竞争、比赛、投标 | 战征 |
| 说不清，就是想看看 | 时运 |

> 注意「战征」这一栏：高岛原文是冷兵器语境（"主将才力微薄""防有兵变"），
> 平移成现代竞争要谨慎，**建议只在用户明确问竞争/对抗时使用，且原文照登不加解释**。

## 5. 分层实施：让 AI 从「最小权限」进入

### P0 · 检索器（不做 AI）

- 页面顶部：**你的问题是哪一类？** 12 个桶，点选
- 依据朱熹七条定出主爻/次爻
- 展示：卦辞、爻辞、大象、高岛该爻「断曰」主体、**该类别对应的那一段**
- 折叠：次爻断语、本卦总论、变卦总论

**成本：半天。零 AI 风险。** 这一步做完，解卦产品已经能用了。

### P1 · 自然语言归类（AI 只干一件小事）

- 用户直接写问题：「我想辞职做自媒体，能成吗」
- **AI 只输出一个类别标签**（如 `营商`），不写任何解释
- 界面上让用户看到"已归类为：营商"，可一键改

> 为什么先做这一步：**分类错了用户能立刻发现并纠正**，代价几乎为零。
> 这是让 AI 进门最安全的方式 —— 它只做一件可被用户验证的事。

**成本：1 天**（接个便宜模型 + 12 分类 prompt）。

### P2 · 白话转述（AI 才真正开始说话）

- 输入 = 用户问题 + 命中的原文（几百字）
- 输出 = 一段白话，**每句标注出自哪段原文**
- 明确分区：`高岛原文` ｜ `AI 转述（非原文）`

**成本：2 天**（含 prompt 调优 + 引用校验）。

## 6. 输出结构：原文在前，AI 在后

```
┌────────────────────────────────────┐
│ 天风姤 ䷫  →  风山渐 ䷴   动爻：二、四 │
├────────────────────────────────────┤
│ ▌为什么看这一句                      │
│  两爻动 → 本卦两动爻，以上爻为主       │
│  → 取《姤》九四                     │
├────────────────────────────────────┤
│ ▌高岛断语（问营商）                  │
│  「包无鱼」，有囊里空虚之象，何以获利？  │
├────────────────────────────────────┤
│ ▌高岛断语（全文）         [ 展开 ]   │
│  断曰：卦象为天下有风，风之起也……     │
├────────────────────────────────────┤
│ ▌原文                               │
│  九四：包无鱼，起凶。                 │
│  卦辞：女壮，勿用取女。               │
├────────────────────────────────────┤
│ ▌AI 转述（非原文）        [ 展开 ]   │
│  ……（每句标出处）                    │
└────────────────────────────────────┘
```

**这个顺序是刻意的**：用户先读到原文，AI 是补充不是主体。
即使 AI 挂了、胡说、被下架，产品依然完整可用。

## 7. 数据缺口（要补）

| 问题 | 数量 | 处理 |
|---|---|---|
| 爻断语缺失（只有爻辞，无高岛断） | **12 爻 / 384**（3.1%） | 落空时回退到「本卦总论 + 爻辞」，并标"此爻无断" |
| 类别覆盖不全 | 婚姻仅 58%、失物仅 30% | 缺时回退到「断曰主体」，不假装有 |
| 战征语义是古代战争 | 336 爻 | 只在明确问竞争时用，原文照登 |
| 34 个原始类别命名不统一 | 商业/营商、婚嫁/婚姻、仕途/功名… | 已归并成 12 桶，映射表见第 4 节 |

缺失的 12 爻主要是《风天小畜》全卦（6 爻），这是数据源本身的问题，可在 P0 之后单独补。

## 8. 版权（这版绕不过去了）

摇卦器不碰文本，没问题。但**解卦产品 95% 的内容是文本**，所以：

- 高岛吞象原著（1884，日文）→ 公有领域 ✅
- 我手里这份**中文译本** → ⚠️ 来源不明、无 license
- 公开上线前必须二选一：
  a. 换公有领域底本（文言，需自己标点）
  b. 自己重译关键段（工作量大，但可控）

**在这件事定下来之前，解卦只适合自己做/给朋友用。**

---

## 9. 我的建议

1. **这一版不做解卦**，摇卦器保持干净，先挂公网让人用起来
2. 解卦单独做，从 **P0 检索器** 开始 —— 半天就能看到效果
3. AI 从 **P1 分类** 进门，观察一段时间再上 P2 转述
4. 版权解决好之前，别公开挂解卦

如果你认同，我下一步可以先做 P0：**用 `takashima_parsed.json` 做一个「点类别 → 出原文」的最简页面**，不接任何模型。
